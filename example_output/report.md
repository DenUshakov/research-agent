# Retrieval-Augmented Generation (RAG): Що це таке та як він доповнює LLM

## 1. Вступ та визначення

**Retrieval-Augmented Generation (RAG)**, або *Генерація із залученням пошуку* — це архітектурний підхід та техніка в галузі штучного інтелекту, яка поєднує **пошукову систему (retriever)** із **великою мовною моделлю (LLM, generator)**. 

Концепцію RAG уперше запропонували дослідники Meta AI у 2020 році (Lewis et al.). Основна ідея полягає в тому, що перед тим як згенерувати відповідь на запит користувача, система здійснює пошук релевантної інформації у зовнішній (або внутрішній корпоративній) базі даних, доповнює цією інформацією контекст запиту та передає його мовній моделі для створення точної й актуальної відповіді.

---

## 2. Чому LLM потребують доповнення (Обмеження традиційних LLM)

Автономні великі мовні моделі (наприклад, GPT-4, Llama 3) є потужними інструментами, але мають декілька суттєвих системних обмежень:

1. **Галюцинації (Hallucinations):** Моделі генерують відповіді на основі статистичних ймовірностей наступного слова. Якщо моделі бракує точних знань, вона може впевнено згенерувати переконливий, але повністю вигаданий факт або неіснуюче посилання.
2. **Застарілість знань (Static Knowledge / Knowledge Cutoff):** Навчання LLM — це дорогий і тривалий процес. Після завершення навчання знання моделі заморожуються. Модель не знає про події, що відбулися після дати завершення її навчання.
3. **Відсутність доступу до приватних/корпоративних даних:** Загальні мовні моделі не мають доступу до внутрішньої документації компанії, бази CRM, приватних баз знань або актуальних тарифів.
4. **Проблема «чорного ящика» (Lack of Traceability):** Звичайні LLM не можуть надати чітких посилань на першоджерела своїх тверджень, що ускладнює перевірку фактів (fact-checking).

---

## 3. Як саме RAG доповнює та покращує LLM

RAG розв'язує зазначені обмеження, не змінюючи власні внутрішні вагові коефіцієнти (weights) мовної моделі, а збагачуючи її контекст у режимі реального часу:

* **Актуалізація знань без перенавчання:** Замість того, щоб повторно навчати модель за мільйони доларів, достатньо додати нові або оновлені документи до зовнішньої бази даних.
* **Зниження рівня галюцинацій:** Оскільки мовна модель отримує точний контекст безпосередньо у промпті, її завдання зміщується з *«пригадай факт із пам'яті»* на *«проаналізуй наданий текст і дай відповідь на його основі»*.
* **Приватність та безпека даних:** Корпоративні дані зберігаються у захищених внутрішніх базах і передаються в LLM тільки у вигляді фрагментів (chunks) під час виконання конкретного запиту.
* **Прозорість та можливість верифікації (Citations):** RAG дозволяє додавати у відповідь безпосередні посилання на використані джерела та цитати, що дозволяє користувачеві самостійно перевірити достовірність.

## 4. Основні етапи роботи RAG-системи

Типовий процес RAG складається з трьох ключових фаз:

```
[ Документи ] ──► [ Chunking & Embedding ] ──► [ Векторна БД ]
                                                    │
[ Запит користувача ] ──► [ Пошук (Retrieval) ] ────┘
                                   │
                           [ Контекст + Запит ]
                                   │
                                   ▼
                           [ LLM (Generation) ] ──► [ Точна відповідь ]
```

### Етап 1: Підготовка та індексація даних (Indexing)
1. **Розбиття на фрагменти (Chunking):** Документи (PDF, HTML, бази знань) розбиваються на невеликі смислові блоки.
2. **Векторизація (Embedding):** Кожен фрагмент перетворюється на числовий вектор (embedding) за допомогою спеціальної мовної моделі.
3. **Збереження у векторній БД:** Вектори зберігаються у векторних базах даних (Vector Store / Vector DB, напр., Chroma, Pinecone, Qdrant).

### Етап 2: Пошук та збагачення (Retrieval & Augmentation)
1. **Пошук релевантного контексту:** Запит користувача векторизується, після чого система знаходить у векторній БД фрагменти тексту з найбільшою семантичною подібністю (semantic search / hybrid search).
2. **Формування збагаченого промпту:** Знайдені фрагменти об'єднуються із початковим запитом користувача у єдине системне повідомлення (Augmented Prompt).

### Етап 3: Генерація (Generation)
1. **Синтез відповіді:** Мовна модель (LLM) зчитує збагачений промпт та генерує відповідь, спираючись безпосередньо на надані факти з знайдених документів.

## 5. RAG vs. Fine-Tuning: Порівняльний аналіз

| Критерій | Retrieval-Augmented Generation (RAG) | Fine-Tuning (Донавчання) |
| :--- | :--- | :--- |
| **Аналогія** | Надати кухарю **книгу рецептів** під час готування | Відправити кухаря на **кулінарні курси** |
| **Основна мета** | Надання доступу до зовнішніх фактів та динамічних даних | Зміна стилю, тону, формату або спеціалізація на термінології |
| **Оновлення даних** | Миттєве (шляхом оновлення баз даних) | Потребує повторного перенавчання (compute-intensive) |
| **Прозорість (Джерела)** | Висока (надає посилання на конкретні джерела) | Низька (знання розчинені у вагах моделі) |
| **Вартість та ресурси** | Низька вартість обслуговування | Високі витрати на обчислювальні ресурси (GPU) |
| **Галюцинації** | Значно зменшені | Можуть залишатися високими |

---

## 6. Висновки

**RAG (Retrieval-Augmented Generation)** є ключовим архітектурним стандартом для побудови сучасних корпоративних AI-систем, чат-ботів та інтелектуальних помічників. Поєднуючи точности й актуальність пошукових систем з гнучкістю та розумінням природної мови з боку LLM, RAG робить використання штучного інтелекту безпечним, точно орієнтованим на факти та економічно ефективним.
