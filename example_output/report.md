# Комплексне порівняння оркестраторів контейнерів: Docker Swarm, Kubernetes та Nomad

У сучасній розробці та DevOps оркестрація контейнерів є фундаментом побудови відмовостійких, масштабованих та розподілених систем. Серед різноманіття рішень на ринку виділяються три ключові гравці: **Docker Swarm**, **Kubernetes (K8s)** та **HashiCorp Nomad**.

Кожен із цих інструментів утілює власну філософію, має свої сильні та слабкі сторони, а також орієнтований на певні сценарії використання.

---

## 1. Архітектура та філософія

### 🐳 Docker Swarm
* **Філософія:** Вбудована простота («Batteries included, but removable»).
* **Архітектура:**
  * Swarm Mode інтегрований безпосередньо в **Docker Engine**.
  * Кластер складається з вузлів-менеджерів (**Manager nodes**) та робочих вузлів (**Worker nodes**).
  * Менеджери використовують алгоритм консенсусу Raft для координації стану кластера та вибору лідера.
* **Основний підхід:** Мінімальні зусилля для старту — якщо у вас встановлено Docker, у вас уже є Swarm.

### ☸️ Kubernetes (K8s)
* **Філософія:** Всеохопна, модульна та розширювана платформа для автоматизації (де-факто стандарт індустрії).
* **Архітектура:**
  * **Control Plane:** Сервер API (`kube-apiserver`), сховище стану (`etcd`), планувальник (`kube-scheduler`), контролер-менеджер (`kube-controller-manager`).
  * **Node Components:** `kubelet` (агент на вузлі), `kube-proxy` (мережевий проксі), Container Runtime (CRI: Containerd, CRI-O).
  * Використовує **декларативну модель узгодження стану (Reconciliation Loop)** та розширюваність через CRD (Custom Resource Definitions) та Operators.

### 🏹 HashiCorp Nomad
* **Філософія:** Гнучкий, легковажний та вузькоспеціалізований планировщик завдань (Workload Orchestrator).
* **Архітектура:**
  * Поставляється у вигляді **єдиного бінарного файлу** (Single Binary).
  * Вузли поділяються на **Servers** (управління та консенсус через Raft) та **Clients** (виконання завдань).
  * Фокусується **виключно на плануванні та оркестрації**, делегуючи мережеві функції (Consul) та управління секретами (Vault) іншим спеціалізованим інструментам екосистеми HashiCorp.

## 2. Ключові критерії порівняння

### A. Типи робочих навантажень (Workload Support)
* **Docker Swarm:** Орієнтований виключно на Docker-контейнери.
* **Kubernetes:** Орієнтований на контейнеризовані навантаження (Containerd, CRI-O), хоча за допомогою розширень (наприклад, KubeVirt) може запускати й віртуальні машини.
* **Nomad:** **Універсальний оркестратор.** "З коробки" підтримує:
  * Контейнери (Docker, Podman);
  * Ізольовані бінарні файли (Raw Exec, Exec);
  * Java-додатки (JAR);
  * Віртуальні машини (QEMU / Firecracker).

### B. Складність, конфігурація та крива навчання
* **Docker Swarm:** Найнижчий поріг входження. Використовує звичний синтаксис `docker-compose.yml` з додаванням секції `deploy`. Запуск кластера здійснюється однією командою `docker swarm init`.
* **Kubernetes:** Високий поріг входження. Вимагає розуміння багатьох абстракцій (Pods, Deployments, ReplicaSets, Services, Ingress, PV/PVC, ConfigMaps, Secrets, RBAC). Конфігурації описуються в YAML/JSON або через Helm-чарти.
* **Nomad:** Середній поріг входження. Використовує мову конфігурації **HCL (HashiCorp Configuration Language)**. Файли завдань (Job files) мають чітку ієрархію: `Job -> Group -> Task`.

### C. Масштабованість та продуктивність
* **Docker Swarm:** Ефективний для малих та середніх кластерів (до кількох сотень нод або ~1,000 нод). При подальшому зростанні продуктивність Raft-консенсусу менеджерів та внутрішньої мережі може знижуватися.
* **Kubernetes:** Офіційно підтримує кластери до **5 000 вузлів** та **150 000 подів** (до 300 000 контейнерів). Багатокомпонентність вимагає значних ресурсів на самих вузлах управління (Control Plane Overhead).
* **Nomad:** Продемонстрував виняткову масштабованість (тест *Million Container Challenge* — запуск 1 млн контейнерів на 10 000+ вузлів за кілька хвилин). Дуже низьке споживання ресурсів самим оркестратором.

### D. Екосистема, інтеграції та ліцензування

| Параметр | Docker Swarm | Kubernetes | Nomad |
| :--- | :--- | :--- | :--- |
| **Організація** | Docker Inc. / Moby Project | CNCF (Cloud Native Computing Foundation) | HashiCorp (IBM) |
| **Ліцензія** | Open Source (Apache 2.0) | Open Source (Apache 2.0) | **BSL 1.1** (Business Source License)* |
| **Екосистема** | Середня (Portainer, Traefik) | Гігантська (Helm, Istio, Prometheus, ArgoCD) | Екосистема HashiCorp (Consul, Vault, Terraform) |

*\*Примітка щодо ліцензії Nomad: У серпні 2023 року HashiCorp перевела Nomad на BSL 1.1. Для більшості внутрішніх розгортань компаніями це безкоштовно, але створює обмеження для надання Nomad як платного сервісу (SaaS/PaaS).*

### E. Мережі, Storage та Service Discovery
* **Docker Swarm:** Вбудована Overlay-мережа, вбудована балансировка навантаження (IPVS) та внутрішній DNS. Підтримка базових Docker Volume Plugins.
* **Kubernetes:** Використовує CNI (Flannel, Calico, Cilium), підтримує повноцінний стандартизований інтерфейс сховищ **CSI (Container Storage Interface)**, Service Mesh (Istio, Linkerd) та Ingress-контролери (Nginx, Traefik, Envoy).
* **Nomad:** Покладається на **Consul** для Service Discovery та Service Mesh (Consul Connect). Підтримує стандарти CSI для підключення сховищ (Ceph, NFS, EBS тощо).

## 3. Детальна порівняльна таблиця (Head-to-Head)

| Критерій | Docker Swarm | Kubernetes (K8s) | HashiCorp Nomad |
| :--- | :--- | :--- | :--- |
| **Головна мета** | Простота та легкий старт | Повний контроль над хмарною інфраструктурою | Гнучка та масштабована оркестрація будь-яких навантажень |
| **Час розгортання** | 2–5 хвилин | 30–60+ хвилин (або K3s/Managed K8s) | 10–20 хвилин |
| **Типи навантажень** | Тільки контейнери | Контейнери (та ВМ через KubeVirt) | Контейнери, Java, ВМ, Raw Executables |
| **Формат конфігурації** | Docker Compose (YAML) | K8s Manifests (YAML / JSON) | HCL (Job specification) |
| **Автомасштабування** | Обмежене (потрібні сторонні скрипти) | Вбудоване (HPA, VPA, Cluster Autoscaler) | Підтримується (Nomad Autoscaler) |
| **Service Discovery** | Вбудований DNS | CoreDNS + K8s Services | Інтеграція з HashiCorp Consul |
| **Управління секретами** | Вбудовані Swarm Secrets | K8s Secrets (потрібне додаткове шифрування/External Secrets) | Інтеграція з HashiCorp Vault |
| **GUI / Dashboard** | Portainer (зовнішній) | Kubernetes Dashboard, Lens | Офіційний вбудований Web UI |
| **Накладні витрати (Overhead)**| Дуже низькі | Високі (потрібно від 2-4 ГБ RAM на Control Plane) | Дуже низькі (один легкий бінарний файл) |

## 4. Коли і що обрати? (Рекомендації та Use Cases)

### 🟢 Обирайте Docker Swarm, якщо:
1. **Мала команда або стартап:** Немає виділеного DevOps-інженера чи ресурсу на обслуговування складного кластера.
2. **Існуючий досвід з Docker Compose:** Увесь стек уже описаний у `docker-compose.yml`, і потрібно швидко отримати високу доступність (High Availability) на кількох серверах.
3. **Обмежені ресурси:** Сервери мають невеликий обсяг RAM/CPU (наприклад, Edge-пристрої, Homelab або невеликі VPS).

### 🔵 Обирайте Kubernetes, якщо:
1. **Стандарт корпоративного рівня:** Потрібен максимальний вибір готових рішень, інструментів CI/CD, GitOps (ArgoCD/Flux) та підтримка спільноти.
2. **Складні мікросервісні архітектури:** Потрібні розширені стратегії деплою (Canary, Blue-Green), Service Mesh, гнучке розмежування прав (RBAC) та складні мережеві політики.
3. **Використання Managed Хмар:** Ви плануєте деплоїти у AWS (EKS), GCP (GKE) або Azure (AKS).

### 🟣 Обирайте Nomad, якщо:
1. **Гібридні навантаження (Mixed Workloads):** Вам потрібно оркеструвати не лише контейнери, а й legacy-застосунки, Java JAR, або башеві скрипти/EXE на тих самих вузлах.
2. **Стек HashiCorp:** Ви вже активно використовуєте Terraform, Consul та Vault.
3. **Величезний масштаб при мінімальних витратах:** Необхідно керувати десятками тисяч вузлів з мінімальними накладними витратами на самі сервери управління.

---

## 5. Підсумковий висновок

* **Docker Swarm** — це найкоротший шлях від локальної розробки до базового продакшну.
* **Kubernetes** — це важка артилерія та індустріальний стандарт, який надає необмежені можливості розширення за рахунок більшої складності.
* **Nomad** — це прагматичний і високопродуктивний інструмент, який робить одну справу (планування задач) на відмінно і без зайвого оверхеду.
